## 개요

일반 유저의 입장에서 위치 증빙 및 출퇴근 기능을 사용하는 다양한 시나리오를 분석하고, 각 시나리오별 고객 여정과 UX 플로우를 정의합니다.

## 핵심 가정

1. **QR 코드 기반 접근**: 센터/조직별 고유 QR 코드를 통해 빠른 접근 제공
2. **비로그인 사용자 지원**: QR 스캔 시 최소한의 인증으로 즉시 사용 가능
3. **로그인 사용자 최적화**: 웹사이트 내에서 직접 출퇴근 기능 사용
4. **위치 기반 검증**: 모든 증빙은 GPS 위치 정보 포함

## 시나리오 1: 비로그인 유저 - 센터 QR로 위치증빙

### 사용자 컨텍스트
- **사용자 상태**: 로그인하지 않음
- **목적**: 센터에 위치 증빙 기록
- **접근 방법**: 센터 QR 코드 스캔
- **증빙 타입**: 일반 위치 증빙 (GENERAL)

### 고객 여정

#### 1단계: QR 코드 스캔
- **액션**: 센터에 부착된 QR 코드를 스마트폰 카메라로 스캔
- **기대 결과**: QR 코드에 인코딩된 센터 정보 인식
- **QR 코드 형식**: `https://prove-geo.app/qr/center/{centerId}?action=proof`

#### 2단계: 웹페이지 로드
- **액션**: QR 코드 스캔 후 웹페이지 자동 이동
- **표시 내용**:
  - 센터 이름
  - "위치 증빙" 안내 메시지
  - 위치 권한 요청 안내
- **상태**: 비로그인 상태

#### 3단계: 인증 선택
- **옵션 A**: 간단한 인증 (이메일/전화번호 입력)
- **옵션 B**: 소셜 로그인 (Google, Apple)
- **옵션 C**: 기존 계정 로그인
- **UX**: 간단한 인증을 우선 제시, 필요시 로그인 유도

#### 4단계: 위치 권한 요청
- **액션**: 브라우저 위치 권한 요청

- **위치 정보**: PostGIS `geom` 필드에서 위치 정보 조회
- **거리 계산**: `ST_Distance` 함수로 거리 계산
- **RLS 정책**: 본인 증빙만 조회 가능 (user_id = auth.uid())

### 특별 고려사항

- **투명성**: 위치 검증 과정의 투명성 제공
- **디버깅**: 검증 실패 시 원인 파악을 위한 상세 정보 제공
- **신뢰성**: 검증 결과의 신뢰성을 높이기 위한 상세 정보 제공
