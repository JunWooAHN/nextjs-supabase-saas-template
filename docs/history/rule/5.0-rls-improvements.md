# RLS 정책 개선 방안 (v5.0)

**작성 일시**: 2025년 11월 17일  
**목표**: 복잡한 RLS 정책을 단순화하고 성능을 개선

---

## 문제점 분석

### 현재 RLS 정책의 문제점

1. **복잡한 JOIN 쿼리**
   - `location_proofs` SELECT 정책에서 `center_org_relationships`와 JOIN
   - `projects` UPDATE 정책에서도 JOIN 사용
   - RLS 정책이 복잡할수록 성능 저하 가능성

2. **중복된 로직**
   - 권한 체크 로직이 여러 정책에 반복됨
   - 비트 연산 로직이 여러 곳에 중복

3. **유지보수 어려움**
   - 정책 수정 시 여러 곳을 수정해야 함
   - 디버깅이 어려움

4. **성능 이슈**
   - JOIN이 많을수록 쿼리 실행 시간 증가
   - 인덱스가 없으면 더 느려짐

---

## 개선 방안

### 방안 1: PostgreSQL Helper 함수 사용 (권장)

**핵심 아이디어**: 복잡한 권한 체크 로직을 PostgreSQL 함수로 추상화

#### 1.1 권한 체크 Helper 함수

```sql
-- lib/permissions.ts의 상수와 일치하는 값 사용
-- 함수: 사용자가 엔티티에 특정 권한이 있는지 확인
CREATE OR REPLACE FUNCTION public.user_has_entity_permission(
  p_user_id UUID,
  p_entity_id UUID,
  p_entity_type SMALLINT,
  p_required_permission BIGINT
)
RETURNS BOOLEAN
LANGUAGE plpgsql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
BEGIN
  RETURN EXISTS (
    SELECT 1
    FROM memberships m
    WHERE m.user_id = p_user_id
      AND m.entity_id = p_entity_id
      AND m.entity_type = p_entity_type
      AND (m.permissions & p_required_permission) <> 0
  );
END;
$$;

-- 함수: 사용자가 센터를 통해 조직에 접근할 수 있는지 확인
CREATE OR REPLACE FUNCTION public.user_can_access_org_via_center(
  p_user_id UUID,
  p_organization_id UUID
)
RETURNS BOOLEAN
LANGUAGE plpgsql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
BEGIN
  RETURN EXISTS (
    SELECT 1
    FROM memberships m
    JOIN center_org_relationships cor ON cor.center_id = m.entity_id
    WHERE m.user_id = p_user_id
      AND m.entity_type = 2 -- CENTER
      AND cor.organization_id = p_organization_id
      AND (m.permissions & 4096) <> 0 -- CENTER_MANAGE_ORGS
  );
END;
$$;

-- 함수: 사용자가 위치 증빙을 조회할 수 있는지 확인 (통합)
CREATE OR REPLACE FUNCTION public.user_can_view_location_proof(
  p_user_id UUID,
  p_proof_user_id UUID,
  p_proof_entity_id UUID,
  p_proof_entity_type SMALLINT
)
RETURNS BOOLEAN
LANGUAGE plpgsql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
BEGIN
  -- 1. 본인이 생성한 증빙인 경우
  IF p_user_id = p_proof_user_id THEN
    RETURN TRUE;
  END IF;

  -- 2. 증빙이 조직(type=1) 소속이고, 내가 그 조직의 관리자인 경우
  IF p_proof_entity_type = 1 THEN
    IF public.user_has_entity_permission(
      p_user_id,
      p_proof_entity_id,
      1, -- ORGANIZATION
      4  -- ORG_MANAGE_MEMBERS
    ) THEN
      RETURN TRUE;
    END IF;

    -- 4. 증빙이 조직(type=1) 소속이고, 내가 그 조직을 관리하는 센터의 관리자인 경우
    IF public.user_can_access_org_via_center(p_user_id, p_proof_entity_id) THEN
      RETURN TRUE;
    END IF;
  END IF;

  -- 3. 증빙이 센터(type=2) 소속이고, 내가 그 센터의 관리자인 경우
  IF p_proof_entity_type = 2 THEN
    IF public.user_has_entity_permission(
      p_user_id,
      p_proof_entity_id,
      2, -- CENTER
      4096 -- CENTER_MANAGE_ORGS
    ) THEN
      RETURN TRUE;
    END IF;
  END IF;

  RETURN FALSE;
END;
$$;
```

#### 1.2 개선된 RLS 정책

**Before (복잡한 JOIN):**
```sql
CREATE POLICY "Users can view location proofs" ON location_proofs
  FOR SELECT USING (
    (location_proofs.user_id = auth.uid()) OR
    (location_proofs.entity_type = 1 AND EXISTS (
      SELECT 1 FROM memberships m
      WHERE m.user_id = auth.uid()
        AND m.entity_id = location_proofs.entity_id
        AND m.entity_type = 1
        AND (m.permissions & 4) <> 0
    )) OR
    -- ... 더 많은 복잡한 조건들
    (location_proofs.entity_type = 1 AND EXISTS (
      SELECT 1
      FROM memberships m
      JOIN center_org_relationships cor ON cor.center_id = m.entity_id
      WHERE m.user_id = auth.uid()
        AND m.entity_type = 2
        AND cor.organization_id = location_proofs.entity_id
        AND (m.permissions & 4096) <> 0
    ))
  );
```

**After (함수 사용):**
```sql
CREATE POLICY "Users can view location proofs" ON location_proofs
  FOR SELECT USING (
    public.user_can_view_location_proof(
      auth.uid(),
      location_proofs.user_id,
      location_proofs.entity_id,
      location_proofs.entity_type
    )
  );
```

#### 1.3 다른 테이블에도 적용

**entity_subscriptions:**
```sql
CREATE POLICY "Managers can view subscriptions" ON entity_subscriptions
  FOR SELECT USING (
    public.user_has_entity_permission(
      auth.uid(),
      entity_subscriptions.entity_id,
      entity_subscriptions.entity_type,
      CASE 
        WHEN entity_subscriptions.entity_type = 1 THEN 4  -- ORG_MANAGE_MEMBERS
        WHEN entity_subscriptions.entity_type = 2 THEN 4096 -- CENTER_MANAGE_ORGS
        ELSE 0
      END
    )
  );
```

**projects:**
```sql
CREATE POLICY "Users can edit projects" ON projects
  FOR UPDATE USING (
    public.user_has_entity_permission(
      auth.uid(),
      projects.org_id,
      1, -- ORGANIZATION
      16 -- ORG_EDIT_PROJECTS
    ) OR
    public.user_can_access_org_via_center(auth.uid(), projects.org_id)
  );
```

### 방안 2: 인덱스 최적화

**RLS 정책에서 자주 사용되는 컬럼에 인덱스 추가**

```sql
-- memberships 테이블 인덱스 (이미 있을 수 있음)
CREATE INDEX IF NOT EXISTS idx_memberships_user_entity 
  ON memberships(user_id, entity_id, entity_type);

CREATE INDEX IF NOT EXISTS idx_memberships_user_type 
  ON memberships(user_id, entity_type);

CREATE INDEX IF NOT EXISTS idx_memberships_permissions 
  ON memberships USING GIN (permissions);

-- center_org_relationships 인덱스
CREATE INDEX IF NOT EXISTS idx_center_org_center 
  ON center_org_relationships(center_id);

CREATE INDEX IF NOT EXISTS idx_center_org_org 
  ON center_org_relationships(organization_id);

-- location_proofs 인덱스
CREATE INDEX IF NOT EXISTS idx_location_proofs_user 
  ON location_proofs(user_id);

CREATE INDEX IF NOT EXISTS idx_location_proofs_entity 
  ON location_proofs(entity_id, entity_type);

-- entity_subscriptions 인덱스
CREATE INDEX IF NOT EXISTS idx_entity_subscriptions_entity 
  ON entity_subscriptions(entity_id, entity_type);
```

### 방안 3: 뷰(View) 활용 (선택적)

**복잡한 조회가 자주 필요한 경우 뷰 사용**

```sql
-- 사용자가 접근 가능한 조직 목록 뷰
CREATE VIEW user_accessible_organizations AS
SELECT DISTINCT
  o.id,
  o.name,
  m.permissions,
  m.entity_type
FROM organizations o
JOIN memberships m ON m.entity_id = o.id
WHERE m.user_id = auth.uid()
  AND m.entity_type = 1
UNION
SELECT DISTINCT
  o.id,
  o.name,
  m.permissions,
  2 as entity_type -- 센터를 통해 접근
FROM organizations o
JOIN center_org_relationships cor ON cor.organization_id = o.id
JOIN memberships m ON m.entity_id = cor.center_id
WHERE m.user_id = auth.uid()
  AND m.entity_type = 2
  AND (m.permissions & 4096) <> 0;

-- RLS 정책 적용
ALTER VIEW user_accessible_organizations SET (security_invoker = true);
```

## 주의사항

### 1. SECURITY DEFINER 사용

- Helper 함수는 `SECURITY DEFINER`로 실행됨
- 함수 내부에서 `auth.uid()` 사용 시 주의 필요
- 함수 파라미터로 `user_id`를 명시적으로 전달하는 것이 안전

### 2. 함수 성능

- `STABLE` 함수로 선언하여 최적화
- 함수 내부 쿼리도 인덱스를 활용할 수 있도록 설계

### 3. 마이그레이션 순서

- 기존 RLS 정책을 한 번에 변경하지 말고 단계적으로
- 각 단계마다 테스트 및 검증

```sql
-- Migration: Improve RLS policies with helper functions
-- Date: 2025-11-17

-- =============================================
-- 1. CREATE HELPER FUNCTIONS
-- =============================================

CREATE OR REPLACE FUNCTION public.user_has_entity_permission(
  p_user_id UUID,
  p_entity_id UUID,
  p_entity_type SMALLINT,
  p_required_permission BIGINT
)
RETURNS BOOLEAN
LANGUAGE plpgsql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
BEGIN

    SELECT 1
    FROM memberships m
    WHERE m.user_id = p_user_id
      AND m.entity_id = p_entity_id
      AND m.entity_type = p_entity_type
      AND (m.permissions & p_required_permission) <> 0
  );
END;
$$;

CREATE OR REPLACE FUNCTION public.user_can_access_org_via_center(
  p_user_id UUID,
  p_organization_id UUID
)
RETURNS BOOLEAN
LANGUAGE plpgsql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
BEGIN
  RETURN EXISTS (
    SELECT 1
    FROM memberships m
    JOIN center_org_relationships cor ON cor.center_id = m.entity_id
    WHERE m.user_id = p_user_id
      AND m.entity_type = 2
      AND cor.organization_id = p_organization_id
      AND (m.permissions & 4096) <> 0
  );
END;
$$;

CREATE OR REPLACE FUNCTION public.user_can_view_location_proof(
  p_user_id UUID,
  p_proof_user_id UUID,
  p_proof_entity_id UUID,
  p_proof_entity_type SMALLINT
)
RETURNS BOOLEAN
LANGUAGE plpgsql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
BEGIN
  -- 1. 본인이 생성한 증빙
  IF p_user_id = p_proof_user_id THEN
    RETURN TRUE;
  END IF;

  -- 2. 조직 관리자 또는 센터를 통한 접근
  IF p_proof_entity_type = 1 THEN
    IF public.user_has_entity_permission(p_user_id, p_proof_entity_id, 1, 4) THEN
      RETURN TRUE;
    END IF;
    IF public.user_can_access_org_via_center(p_user_id, p_proof_entity_id) THEN
      RETURN TRUE;
    END IF;
  END IF;

  -- 3. 센터 관리자
  IF p_proof_entity_type = 2 THEN
    IF public.user_has_entity_permission(p_user_id, p_proof_entity_id, 2, 4096) THEN
      RETURN TRUE;
    END IF;
  END IF;

  RETURN FALSE;
END;
$$;

-- =============================================
-- 2. CREATE INDEXES
-- =============================================

CREATE INDEX IF NOT EXISTS idx_memberships_user_entity 
  ON memberships(user_id, entity_id, entity_type);

CREATE INDEX IF NOT EXISTS idx_center_org_org 
  ON center_org_relationships(organization_id);

CREATE INDEX IF NOT EXISTS idx_location_proofs_entity 
  ON location_proofs(entity_id, entity_type);

-- =============================================
-- 3. UPDATE RLS POLICIES
-- =============================================

-- Drop old policies
DROP POLICY IF EXISTS "Users can view location proofs" ON location_proofs;
DROP POLICY IF EXISTS "Managers can view subscriptions" ON entity_subscriptions;
DROP POLICY IF EXISTS "Users can edit projects" ON projects;

-- Create new simplified policies
CREATE POLICY "Users can view location proofs" ON location_proofs
  FOR SELECT USING (
    public.user_can_view_location_proof(
      auth.uid(),
      location_proofs.user_id,
      location_proofs.entity_id,
      location_proofs.entity_type
    )
  );

CREATE POLICY "Managers can view subscriptions" ON entity_subscriptions
  FOR SELECT USING (
    public.user_has_entity_permission(
      auth.uid(),
      entity_subscriptions.entity_id,
      entity_subscriptions.entity_type,
      CASE 
        WHEN entity_subscriptions.entity_type = 1 THEN 4
        WHEN entity_subscriptions.entity_type = 2 THEN 4096
        ELSE 0
      END
    )
  );

CREATE POLICY "Users can edit projects" ON projects
  FOR UPDATE USING (
    public.user_has_entity_permission(auth.uid(), projects.org_id, 1, 16)
    OR
    public.user_can_access_org_via_center(auth.uid(), projects.org_id)
  );

-- =============================================
-- 4. COMMENTS
-- =============================================

COMMENT ON FUNCTION public.user_has_entity_permission IS 
  'Check if user has required permission on entity. Used by RLS policies to simplify complex permission checks.';

COMMENT ON FUNCTION public.user_can_access_org_via_center IS 
  'Check if user can access organization through center membership. Used by RLS policies for cross-entity access.';

COMMENT ON FUNCTION public.user_can_view_location_proof IS 
  'Check if user can view a location proof. Consolidates all location proof access logic into a single function.';
```
